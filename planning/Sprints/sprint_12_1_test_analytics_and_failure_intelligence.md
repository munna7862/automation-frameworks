## 2. Data Model

`results-history/YYYY/MM/<run_id>-<framework>.json` on `gh-pages`:
```json
{
  "schemaVersion": 1,
  "runId": "1234567890", "runAttempt": 1, "workflow": "nightly-regression",
  "framework": "playwright", "project": "chrome", "targetEnv": "DOCKER",
  "commit": "abc1234", "branch": "main", "event": "schedule",
  "startedAt": "2026-10-05T01:30:00Z", "durationMs": 412345,
  "tests": [
    { "id": "UI-CHK-001", "title": "…", "file": "src/tests/ui/Checkout/…", "status": "passed|failed|flaky|skipped",
      "retries": 0, "durationMs": 8123, "errorSignature": "TimeoutError: locator.click …#a1b2", "category": "test-bug" }
  ]
}
```
- `id` = catalog ID extracted from the title prefix (e.g. `API_ORD_01`), falling back to `file::title`.
- `errorSignature` = first error line with volatile parts (numbers, ids, URLs) normalised, plus a short hash.

## 3. Sprint Backlog & User Stories

### US-AF-1211: Results normaliser & collection (1.5 SP)
- [ ] `scripts/analytics/normalize-results.ts` — adapters for Playwright JSON (`results.json`), Allure results (Selenium/WDIO/Mobile), and k6 summary (scenario-level pass/fail).
- [ ] Reusable workflow step (after tests, `if: always()`) → produces the normalised JSON artifact; the deploy job commits it under `results-history/` on gh-pages (same `pages-deploy-allure` concurrency group).
- [ ] Retention script: keep 90 days of raw files; roll older ones into `results-history/aggregates/YYYY-MM.json`.

### US-AF-1212: KPIs & portal analytics page (1.5 SP)
- [ ] `scripts/analytics/compute-kpis.ts` → `docs/portal/analytics-data.json`:
  - **Flakiness index** per test = flaky or (failed-then-passed) runs ÷ total runs over the last 30 days.
  - Pass-rate trend per framework (daily).
  - **MTTR** for `main`: time from first red nightly to next green.
  - Top 10 slowest tests and top 10 most frequent error signatures.
  - Quarantine age (from `@quarantine` tags + git blame date) vs the 14-day policy.
  - Includes a11y violations (`a11y-summary.json`, Sprint 10.2) and security finding counts (Sprint 9.1) if present.
- [ ] `docs/portal/analytics.html` (linked from the portal index), styled consistently with the existing portal; Chart.js from cdnjs.
- [ ] `quarantine-audit.yml` reads the flakiness index and suggests **new** quarantine candidates (index > 10%) in its summary.

### US-AF-1213: Failure classification (1 SP)
- [ ] `playwright-e2e/allure-categories.json` (copied into `allure-results/categories.json` before report generation) plus the same for Selenium/WDIO/Mobile:
  | Category | Matched by |
  | :--- | :--- |
  | Environment | `ECONNREFUSED`, `ECONNRESET`, `502`, `503`, `504`, `wait-on`, `net::ERR_` |
  | Known intentional bug | Test annotated `intentional-bug` (Playwright `test.info().annotations`) or `test.fail()` |
  | Test defect | `strict mode violation`, `locator.*Timeout`, `toHaveScreenshot` diff, `Target closed` |
  | Product defect | Assertion failures on business values (`expect(received).toBe…`) not matched above |
- [ ] The normaliser applies the same rules to set `category`.

### US-AF-1214: Sticky PR results comment (1 SP)
- [ ] In `pr-gate.yml`: `marocchino/sticky-pull-request-comment` (SHA-pinned) with `header: test-results`, body generated by `scripts/analytics/pr-comment.ts`:
  - Results table per job (smoke, burn-in, security baseline, k6 drift).
  - **New failures vs `main`** (compares against the latest main nightly history file).
  - Links: Monocart artifact, Allure, ZAP, k6 report.
- [ ] `permissions: pull-requests: write` only on that job.

## 5. Code Review Checklist

- [ ] Normaliser handles retries correctly (a test that failed then passed = `flaky`, counted once).
- [ ] Error-signature normalisation strips volatile data (timestamps, uuids, ports).
- [ ] The history commit uses the same Pages concurrency group (no races) and doesn't clobber Allure folders.
- [ ] KPI definitions are documented in `docs/architecture/reporting_architecture.md`.
- [ ] Unit tests for the normaliser (fixtures for each adapter) and the classifier rules.
